## 1. 노트북 구조 요약

`Windforce` 패키지 클래스를 활용해 **데이터 로드 → 격자 전처리 → 그룹 공간집계 → 모형 학습 → 제출**까지 재현 가능하게 구성한 OOP 파이프라인 노트북 (총 38개 셀).

| Step | 내용 | 사용 클래스 |
| --- | --- | --- |
| 1 | 파일 경로 존재 확인 | `WindforceDataLoader.check_paths()` |
| 2 | 데이터 구조 확인 (SCADA, train_labels, ldaps/gfs, kpx_info) | `WindforceDataLoader` |
| 3 | 터빈 메타 준비 — DMS 좌표 → 십진 위경도, `turbine_meta`(group/lat/lon/cap_kw) 생성 | 커스텀 `parseDMS()` |
| 4 | LDAPS(16격자)·GFS(9격자) 전처리 + KPX 3그룹 IDW 공간집계 | `LDAPSFeatureEngineer`, `GFSFeatureEngineer` |
| 5 | SCADA 파워커브 시각화 (3D 산점도, LOWESS) | `plotly` |
| 6 | 평가지표(NMAE, FICR) 및 미분가능 손실함수 검증 | `EvaluationMetrics`, `ScoreLossFunction` |
| 7 | 그룹별(1/2/3) Persistence·SVR·LSTM 3모델 학습·평가 | `WindforceDatasetBuilder`, `GroupExperimentRunner`, `LSTMPipeline` |
| 8 | 스키마 검증 + `submission_baseline3.csv` 저장 | — |

### 데이터 규모

- LDAPS: 16격자 × 26,304시각(학습) → `transform()` 후 (420,864, 61) → IDW 집계 후 (78,912, 43)
- GFS: 9격자 × 26,304시각(학습) → IDW 집계 후 (78,912, 76)
- SCADA: VESTAS 12기(10분 단위, 157,819행), UNISON 5기(105,264행)
- 평가(2025년) 기간: LDAPS/GFS 전처리 후 각각 (26,280, 43) / (26,280, 76)
- `kpx_group_3`는 2022년 라벨이 없어(2023~2024만 제공) 다른 그룹보다 학습 데이터가 1년 적음

### 대회 지표

- `1-NMAE`: 그룹별 `mean(|pred-actual|/설비용량)`을 1에서 뺀 값 (클수록 좋음)
- `FICR`: 오차율 구간별 정산단가(≤6%: 4원, 6~8%: 3원, >8%: 0원) 기반 정산금 비율 (클수록 좋음)
- 총점 = `0.5×(1-NMAE) + 0.5×FICR`
- `ScoreLossFunction`은 FICR의 계단함수를 시그모이드 2개(steepness `k=300`)로 완화해 미분 가능하게 근사한 커스텀 손실함수

## 2. 정확도가 낮은 원인 (코드 근거 기반)

### 2-1. `ScoreLossFunction`의 시그모이드 steepness(`k=300`)로 인한 그래디언트 소실 — **가장 유력한 근본 원인**

```python
softPrice = 4.0 - 1.0*sigmoid(k*(errorRatio-0.06)) - 3.0*sigmoid(k*(errorRatio-0.08))
```

- `k=300`이면 `errorRatio`가 6%·8% 문턱에서 조금만 벗어나도 시그모이드가 즉시 0 또는 1로 포화되어 **그래디언트가 사실상 0**이 됩니다.
- 학습 초반 LSTM 출력은 ReLU 특성상 0에 가깝고, 그룹1 실제값은 12,000~19,000kWh 수준(설비용량 21,600kWh 대비 오차율 55~88%)이므로 거의 모든 배치 샘플이 8% 문턱에서 완전히 벗어난 채 시작 → FICR 항의 그래디언트가 배치 전체에서 거의 발생하지 않음.
- 실제로 Step 7 학습 로그에서 그룹1(`0.647x`대), 그룹2(`0.659x`대) loss가 30 epoch 내내 **소수점 4자리 수준에서만 진동**하며 사실상 학습이 정체됨. 그룹3만 초반에 완만히 개선되다가 역시 정체.
- 결과적으로 모델이 실질적으로 학습되지 않은 채 초기 가중치 근처(≈상수 출력)에 머무름 → Persistence보다 낮은 점수로 귀결.

### 2-2. 제출 셀(Step 8)의 학습/평가 피처 정렬 버그

```python
test_num_cols = [c for c in test_merged.select_dtypes(include="number").columns if c in feat_cols]
...
scaler = MinMaxScaler().fit(X_train[:, :len(test_num_cols)])
X_train_sc = scaler.transform(X_train[:, :len(test_num_cols)])
```

- `X_train`은 `feat_cols`(학습 데이터 컬럼 순서) 기준으로 만들어졌는데, 평가용 컬럼 목록 `test_num_cols`는 **`test_merged`의 컬럼 순서**를 기준으로 별도로 만들어집니다.
- 두 리스트는 컬럼 이름·순서가 다를 수 있는데도, `X_train[:, :len(test_num_cols)]`는 **개수만 맞춰 앞에서부터 자르는 위치 기반 슬라이싱**입니다. 즉 학습 때 스케일러가 학습한 컬럼과 실제 추론 시 입력되는 컬럼이 이름 기준으로 일치한다는 보장이 없습니다.
- 이 정렬 불일치가 있으면 설령 모델이 학습 구간에서 뭔가 배웠더라도, 평가 시점에는 **다른 의미의 피처가 다른 스케일로 입력**되어 예측이 사실상 랜덤/상수에 가깝게 무너집니다. Step 7(홀드아웃 평가)에서는 같은 `build()` 산출물을 나누어 쓰므로 이 문제가 없지만, Step 8(실전 제출 생성)에서만 발생하는 버그입니다.

### 2-3. 타깃(y) 스케일링 부재

- `y_train`은 kWh 원 단위(수백~수만) 그대로 사용되고, 입력 `X`만 `MinMaxScaler`로 `[0,1]`로 정규화됩니다.
- 초기 가중치가 작은 LSTM+ReLU 조합은 출력이 0 근처에서 시작하는데, 타깃 스케일이 크면 `2-1`의 그래디언트 소실 문제와 겹쳐 상수(≈학습 초기 상태)에 수렴하기 더 쉬워집니다.

### 2-4. 고정 30-epoch, 검증 기반 조기종료·체크포인트 없음

- 학습 곡선(soft loss)만 출력할 뿐, 매 epoch 실제 NMAE/FICR(홀드아웃)을 추적하지 않아 최적 시점을 알 수 없고, 위 문제들과 결합해 “학습이 정체된 상태의 마지막 epoch 가중치”를 그대로 씁니다.

### 2-5. `kpx_group_3` 라벨 공백(2022년) + 상대적으로 적은 학습 데이터

- 그룹1/2는 2022~2024(3년), 그룹3은 2023~2024(2년)만 라벨 존재. 시퀀스 모델(LSTM)은 데이터가 적을수록 위 문제들의 영향을 더 크게 받습니다.

### 2-6. (경미, 확인 필요) IDW 집계 초반 구간 전부 0

- `ldaps_group_df`/`gfs_group_df`의 2022-01-01 첫 며칠 행이 풍속·기온 등 거의 모든 피처에서 0으로 나타남 (`data_available_kst_dtm`이 학습 데이터 시작 이전이라 유효 예보가 없는 첫날 구간으로 추정). 물리적으로 불가능한 값(기온 0K 등)이 학습 초반에 섞여 들어가면 스케일러·모델 초기화에 나쁜 영향을 줄 수 있어, 결측 대신 명시적 마스킹/제외를 확인할 필요가 있습니다.

## 3. “전날 13시까지의 예보로 다음날 24시간 예측” 운영 제약 확인

`data_description.md` 기준 실제 규정:

- 기상 예보는 매일 09:00 KST에 초기화되며, **해당일 13:00 KST부터 사용 가능**한 것으로 간주됩니다.
- 하나의 `data_available_kst_dtm`(예: `2024-12-31 13:00:00`)에 대해 **다음날 01:00 ~ 그다음날 00:00까지 24개 `forecast_kst_dtm`**이 대응됩니다.
- 즉 실제 운영 조건은 “전날 13시 시점에 확보한 예보만으로 다음날 24시간 발전량을 한 번에 예측”하는 **day-ahead(D+1) 일괄 예측** 구조입니다. (사용자가 언급한 “14시”는 근사치이며, 실제 컷오프는 13시입니다.)
- 현재 파이프라인은 `forecast_kst_dtm` 기준으로만 병합하고 `lead_hour`(발행 후 몇 시간째 예보인지, 1~24)를 피처로 갖고 있지만, 이 리드타임 구조를 명시적으로 활용하는 로직(리드타임별 오차 특성 반영, 발행 시점 단위 학습/추론 배치 구성 등)은 아직 없습니다.

## 4. 정확도 개선 방안 (우선순위 순)

### A. 손실함수 그래디언트 소실 해결 (최우선)

- `ScoreLossFunction`의 `k`를 300 → 30~80 수준으로 낮추거나, 학습 초반엔 순수 `MSE`/`Huber`로 워밍업 후 후반부에 FICR 항을 서서히 도입(커리큘럼 학습).
- 또는 `errorRatio`를 sigmoid에 넣기 전 클리핑(예: `[0, 0.2]`)해 극단값에서의 완전 포화를 방지.

### B. Step 8 제출 코드의 피처 정렬 버그 수정

- `X_train[:, :len(test_num_cols)]` 같은 위치 기반 슬라이싱 대신, **컬럼명 기준 교집합**을 구해 학습·평가 양쪽에 동일한 순서로 적용:
    
    ```python
    common_cols = [c for c in feat_cols if c in test_merged.columns]
    X_train = train_df[common_cols].values
    X_test  = test_merged[common_cols].values
    ```
    

### C. 타깃 정규화

- 원시 kWh 대신 **설비용량 대비 이용률(`power/capacity`, 0~1)**을 타깃으로 학습하고 예측 후 역변환. 스케일 문제 해소 + 그룹 간(21,600 vs 21,000 kW) 비교 용이.

### D. 검증 기반 학습 제어

- 매 epoch 홀드아웃에서 실제 NMAE/FICR(soft 근사 아님)을 계산해 최고 시점 가중치를 저장(early stopping), 학습률 스케줄러 도입.

### E. Persistence 대비 잔차 학습(residual modeling)

- 현재 Persistence가 최고 점수(0.796)를 낸다는 것은 “어제와 비슷하다”는 정보가 이미 강력하다는 뜻. LSTM/SVR이 절대 발전량을 직접 맞히기보다 **Persistence 예측값 대비 잔차**를 학습하도록 바꾸면, 학습이 훨씬 쉬워지고 최소 Persistence 수준은 보장하면서 기상 정보로 추가 개선을 노릴 수 있습니다.

### F. SCADA 파워커브를 물리적 사전정보로 활용

- Step 5에서 확인한 S자 파워커브(풍속→발전량)를 터빈 모델별(V126/U136)로 피팅해, 예보 풍속을 이론적 발전량으로 변환한 값을 강력한 피처(또는 앙상블의 한 축)로 추가. 순수 통계 모델보다 물리적 제약을 반영해 일반화에 유리.

### G. 리드타임(`lead_hour`) 구조를 명시적으로 활용

- 예보 발행 시점(13시) 기준 1~24시간 뒤 예측이라는 구조를 살려, `lead_hour`를 강한 피처로 유지하거나 리드타임 구간별(단기 1-8h / 중기 9-16h / 장기 17-24h) 모델을 분리해 학습 — 리드타임이 길수록 예보 오차가 커지는 특성을 모델이 명시적으로 학습하게 함.

### H. 트리 기반 모델(LightGBM/XGBoost) 병행 시도

- 시간당 학습 샘플이 그룹당 2~3만 행 수준으로 딥러닝 시퀀스 모델엔 크지 않은 규모입니다. 정형 피처(풍속·기압·구름량 등) 기반 그래디언트 부스팅이 LSTM보다 안정적으로 더 높은 점수를 낼 가능성이 높으므로, Persistence/SVR/LSTM에 LightGBM을 추가해 비교 실험할 것을 권장합니다.

### I. 시계열 교차검증

- 현재는 마지막 20% 단일 구간 홀드아웃뿐입니다. 계절성(겨울/여름 풍력 발전 패턴 차이)을 반영해 여러 시즌 블록으로 나눈 시계열 CV(예: rolling-origin)로 일반화 성능을 재검증할 필요가 있습니다.

### J. 앙상블

- 위 개선들을 거친 뒤에도, 최종적으로 Persistence·GBM·LSTM(잔차 기반)을 그룹별 최적 가중치로 블렌딩하면 단일 모델보다 안정적인 총점 개선이 기대됩니다.

## 5. 요약 우선순위

1. **A(손실함수) + B(피처 정렬 버그)** — 지금 LSTM이 사실상 작동하지 않는 근본 원인이므로 최우선 수정
2. **C(타깃 정규화) + D(검증 기반 학습 제어)** — 위 수정 후 실제 학습이 되는지 확인하는 단계
3. **E(잔차 학습) + F(파워커브 피처) + G(리드타임 활용)** — Persistence를 실질적으로 능가하기 위한 핵심 개선
4. **H(GBM 비교) + I(시계열 CV) + J(앙상블)** — 모델 선택 고도화 및 최종 안정화
