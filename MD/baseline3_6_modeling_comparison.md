# Baseline 3~6 모델링 차이 비교

> 공동연구자 공유용 · 초심자 설명 버전  
> 작성일: 2026-08-12  
> 비교 기준: IDW 그룹 키 및 첫 24시간 제출 추론 수정이 반영된 **현재 소스 코드**

---

## 1. 먼저 결론

현재 파일을 기준으로 보면 네 버전의 관계는 다음과 같다.

- **Baseline 3**: Persistence, SVR, LSTM을 비교하는 기본 실험이다.
- **Baseline 4**: Baseline 3와 모델링 방식이 사실상 같다. 별도의 새 모델 버전으로 보기 어렵다.
- **Baseline 5**: 같은 모델 구성을 더 명시적이고 안정적으로 실행·기록하도록 정리한 버전이다.
  현재 공통 코드 기준으로는 Baseline 3·4와 LSTM 구조 및 주요 학습값도 같다.
- **Baseline 6**: 세 종류의 LSTM과 네 종류의 피처 구성을 조합해 비교하는 본격적인 실험 버전이다.

쉽게 비유하면 Baseline 3은 첫 실험지, Baseline 4는 거의 같은 실험지의 복사본,
Baseline 5는 실험 절차와 기록 방법을 정돈한 버전, Baseline 6은 여러 선택지를 비교하는
실험 설계표에 가깝다.

## 2. 초심자를 위한 용어

| 용어 | 쉬운 설명 |
|---|---|
| 모델 | 주어진 기상 정보로 발전량을 계산하는 예측 방법 |
| 피처(feature) | 풍속, 풍향, 기온처럼 모델이 참고하는 단서 |
| 학습 | 과거 기상과 실제 발전량을 보고 예측 규칙을 익히는 과정 |
| 검증 | 학습에 쓰지 않은 뒤쪽 기간으로 치르는 모의시험 |
| 손실함수 | 예측이 얼마나 잘못됐는지 모델에 알려주는 학습용 점수표 |
| 하이퍼파라미터 | 학습 횟수, 기억 크기처럼 연구자가 정하는 설정값 |
| 시계열 | 시간 순서가 중요한 데이터. 미래 자료를 과거 학습에 섞으면 안 됨 |
| LSTM | 최근 여러 시간의 흐름을 기억해 다음 값을 예측하는 딥러닝 모델 |

## 3. 네 버전에 공통인 기본 흐름

네 노트북 모두 다음 뼈대를 공유한다.

```text
LDAPS·GFS 기상예보
        ↓
터빈 위치와 용량을 반영한 그룹별 IDW 집계
        ↓
그룹별 기상 피처 + 실제 발전량 결합
        ↓
시간 앞쪽 80% 학습 / 뒤쪽 20% 검증
        ↓
KPX 그룹 1·2·3을 각각 별도 모델로 학습
        ↓
NMAE, FICR, 총점 계산
```

공통 사항은 다음과 같다.

- LDAPS와 GFS에서 만든 숫자형 기상 피처를 모델 입력으로 사용한다.
- SCADA 자료는 파워 커브를 눈으로 확인하는 데 사용하지만, 현재 모델 입력에는 직접 들어가지 않는다.
- 세 KPX 그룹은 설비 구성과 용량이 다르므로 각각 따로 학습한다.
- 데이터를 무작위로 섞지 않고 시간 순서대로 앞 80%와 뒤 20%로 나눈다.
- 스케일러는 학습 구간에서만 계산해 미래 검증 정보가 학습에 새어 들어가지 않게 한다.
- LSTM은 최근 24시간의 기상 흐름으로 바로 다음 시각의 발전량을 예측한다.
- LSTM 출력은 설비용량 대비 0~1 비율로 제한한 뒤 그룹 설비용량을 곱해 발전량으로 바꾼다.

평가 총점은 다음 두 요소를 절반씩 반영한다.

```text
총점 = 0.5 × (1 - 평균 오차율) + 0.5 × 정산금 획득률
```

여기서 NMAE는 낮을수록 좋고, FICR과 최종 총점은 높을수록 좋다.

## 5. Baseline 3

Baseline 3은 세 모델의 역할을 비교하는 기본 실험이다.

### Persistence

바로 전 시각의 **실제 발전량**을 다음 시각 예측으로 그대로 사용한다.
날씨 모델 없이도 만들 수 있는 쉬운 기준선이지만, 미래 평가 기간에는 직전 실제값을 알 수 없으므로
제출 모델로 사용할 수 없다. 현재 코드도 이를 `Persistence_oracle_lag1`로 표시한다.

### SVR

현재 시각의 기상 피처와 발전량 사이의 굽은 관계를 찾는 전통적인 머신러닝 모델이다.
RBF 커널, `C=10`, `epsilon=0.01`을 사용한다. 시간 24개를 한 묶음으로 기억하지 않고
각 행의 기상 조건을 독립적으로 본다.

### LSTM

최근 24시간의 기상 변화 순서를 보고 다음 발전량을 예측한다.
기본 구조는 은닉 크기 64, LSTM 2층이며 마지막 시각의 내부 기억을 이용해 값을 하나 출력한다.

검증에서는 세 모델을 모두 비교하지만 제출 파일은 최고 모델을 자동 선택하지 않는다.
코드상 LSTM을 다시 전체 학습 데이터로 학습해 제출값을 만든다.

## 6. Baseline 4

현재 Baseline 4의 모델, 피처, 분할, LSTM 학습 방식은 Baseline 3과 같다.

실질적인 차이는 다음 정도다.

- 전처리와 공통 유틸리티 import가 더 많이 적혀 있다.
- 제출 파일 이름이 `submission_baseline4.csv`다.
- 노트북 제목은 아직 `Baseline 3`으로 남아 있다.

따라서 Baseline 3과 Baseline 4의 점수가 다르게 나와도 이를 새로운 모델의 효과라고 해석하면 안 된다.
재실행 시점의 공통 패키지 상태, 난수, 기존 출력 상태 등을 먼저 확인해야 한다.

연구 보고서에서는 두 파일을 서로 다른 모델 두 개로 세기보다, 같은 모델링 계열의 반복본으로
분류하는 것이 안전하다.

## 7. Baseline 5

Baseline 5도 Persistence, SVR, LSTM을 비교한다. 핵심은 완전히 새로운 신경망보다는
학습 절차를 분명하게 고정하고 결과를 남기는 데 있다.

### 달라진 운영 방식

- 노트북 안에 있던 데이터셋 조립 클래스를 `Windforce/Modeling`의 공통 클래스로 사용한다.
- 학습 자료를 예보 시각 순으로 명시적으로 정렬한다.
- 오래 열린 Jupyter 커널에서도 최신 모델 코드가 반영되도록 관련 모듈을 다시 불러온다.
- LSTM 학습값을 노트북에 명시한다.
- 그룹·모델별 결과를 `BASELINE/baseline_5_results.csv`로 저장한다.
- 제출 시 학습과 평가에 공통으로 존재하는 피처를 학습 컬럼 순서대로 맞춘다.

### LSTM 학습 방식

Baseline 5의 LSTM은 처음부터 대회 점수 손실만 사용하지 않는다.

1. 처음 15회는 일반적인 회귀 손실로 기본적인 발전량 범위를 익힌다.
2. 이후에는 회귀 손실 75%와 대회 점수 근사 손실 25%를 섞는다.
3. 최대 80회 학습하되 검증 총점이 12회 연속 좋아지지 않으면 멈춘다.
4. 검증 총점이 가장 좋았던 시점의 모델로 되돌아간다.

이는 어려운 채점 기준부터 바로 공부시키지 않고, 기본 문제를 먼저 익힌 뒤 실제 시험 기준을
함께 반영하는 방식으로 이해하면 된다.

### 현재 소스에서의 중요한 점

이 학습 방식은 현재 공통 `LSTMPipeline`의 기본 동작이기도 하다. Baseline 3·4는 값을 생략했지만
동일한 기본값을 받아 사용한다. 또한 첫 24시간 추론과 피처 정렬 수정이 Baseline 3·4에도
소급됐기 때문에, 현재 상태에서 Baseline 5만의 독립적인 모델 개선 폭을 점수로 분리하기는 어렵다.

## 8. Baseline 6

Baseline 6은 하나의 제출 모델을 만드는 노트북이라기보다, 어떤 LSTM 구조와 어떤 피처 구성이
좋은지를 찾는 비교 실험이다.

### 8-1. 세 가지 LSTM

| 모델 | 무엇이 다른가 | 쉬운 비유 |
|---|---|---|
| v1 | 마지막 시각의 LSTM 기억을 사용 | 24시간을 읽고 마지막에 남은 요약만 답에 사용 |
| v2 | v1에 LayerNorm과 Dropout 추가 | 기억을 정돈하고 일부 정보를 일부러 가려 과적합을 줄임 |
| v3 | 24개 시각 전체에 Attention 가중치 적용 | 어느 시간이 중요했는지 가중치를 주어 전체를 다시 참고 |

세 모델 모두 은닉 크기 64, LSTM 2층, 최근 24시간 입력, sigmoid 출력을 사용한다.

다만 v1을 Baseline 5와 완전히 같은 대조군으로 보면 안 된다. Baseline 6의 v1에도 다음 조건이
추가되거나 달라져 있다.

- LSTM 층 사이 Dropout 0.2
- 그래디언트 폭주를 막는 gradient clipping 1.0
- 모델마다 같은 난수 시드를 다시 설정
- 최대 학습 35회, 워밍업 8회, 조기종료 patience 7

Baseline 5는 최대 80회, 워밍업 15회, patience 12이므로 두 결과의 차이는 LSTM 표현 방식뿐 아니라
학습 시간과 안정화 장치의 영향도 함께 포함한다.

### 8-2. 네 가지 피처 방식

| 피처 버전 | 하는 일 | 장점 | 주의점 |
|---|---|---|---|
| `all` | 숫자형 피처를 모두 사용 | 정보를 최대한 보존 | 중복·불필요한 피처도 포함 |
| `corr_filtered` | 상관계수 절댓값이 0.95를 넘는 피처 쌍에서 하나 제거 | 비슷한 정보를 줄임 | 먼저 나온 피처를 남기는 단순 규칙 |
| `pca` | 전체 정보를 95% 설명하는 소수의 합성 피처로 압축 | 차원을 크게 줄일 수 있음 | 새 피처의 의미를 사람이 해석하기 어려움 |
| `tree_importance` | ExtraTrees 중요도 상위 35%를 선택하되 최소 8개 유지 | 타깃과 관련 있는 원래 피처를 남김 | 선택 결과가 트리 모델의 판단에 의존 |

모든 피처 방식은 학습 구간에서만 결측치 대체값과 선택 기준을 계산한다.
검증 구간은 학습에서 정한 규칙으로만 변환하므로 미래 정보 누수를 막는다.

### 8-3. 실험과 평가

총 12개 `LSTM 버전 × 피처 버전` 조합을 세 그룹에서 실행하므로 36번 학습한다.
각 조합의 피처 수, 가장 좋았던 epoch, NMAE, FICR, 총점을 저장한다.

Baseline 6의 조기종료는 현재 코드상 공식 총점이 아니라 **MAE가 가장 작은 시점**을 기준으로 한다.
최종 결과표에서는 공식 NMAE·FICR·총점을 계산하지만, 모델을 멈추고 되돌리는 기준은 다르다.
따라서 “공식 총점 최적화 실험”이라기보다 “MAE로 학습 시점을 고른 뒤 공식 점수로 비교한 실험”으로
설명하는 것이 정확하다.

또한 마지막에는 제출 방법을 설명하는 마크다운만 있고 실제 제출 생성 셀은 없다.
현재 산출물은 `baseline_6_results.csv`와 `baseline_6_summary.csv`이며 제출 CSV는 생성하지 않는다.

## 9. 버전 사이에서 실제로 바뀐 것

```text
Baseline 3 ──┐
             ├─ 같은 Persistence / SVR / LSTM 비교
Baseline 4 ──┘
                    ↓ 실행 절차와 결과 기록을 명확히 정리
Baseline 5 ── 공통 데이터셋 빌더 + 명시적 학습 설정 + 결과 CSV
                    ↓ 모델 구조와 피처 선택을 여러 조합으로 확장
Baseline 6 ── LSTM 3종 × 피처 4종 비교 실험
```

즉, 모델 종류가 실제로 크게 늘어나는 지점은 Baseline 6이다. Baseline 3에서 5까지는 같은 기본
모델군을 유지하면서 코드 구조, 학습 안정화 설명, 결과 관리와 제출 안전성을 정리한 흐름이다.

## 10. 공동연구 시 결과를 해석하는 방법

### 권장 분류

- **기본 비교군**: Persistence, SVR
- **주요 제출 기준 모델**: Baseline 5 LSTM
- **중복 계열**: Baseline 3·4 LSTM
- **구조·피처 탐색 실험**: Baseline 6

### 점수를 비교할 때 주의할 점

1. Baseline 3·4를 서로 다른 모델 성과로 세지 않는다.
2. Baseline 3~5는 같은 공통 `LSTMPipeline` 파일을 사용하므로 패키지 변경 시 과거 버전 동작도 바뀐다.
3. Baseline 5와 Baseline 6은 학습 횟수와 조기종료 기준이 달라 완전한 일대일 비교가 아니다.
4. Persistence는 미래 실제값이 필요한 참고 기준선이므로 제출 가능 모델과 같은 조건으로 보지 않는다.
5. 제출 모델은 검증 결과 1등을 자동 선택하지 않고 Baseline 3~5 모두 LSTM으로 고정돼 있다.
6. IDW 버그 수정 뒤 네 노트북이 모두 재실행된 상태가 아니므로 기존 저장 점수를 그대로 비교하지 않는다.

공정한 논문용 비교를 하려면 동일한 데이터, 동일한 시간 분할, 동일한 학습 횟수와 조기종료 기준을
맞춘 뒤 한 요소만 바꿔야 한다. 예를 들어 Attention 효과를 보려면 v1과 v3의 나머지 조건을 모두
같게 설정해야 한다.

## 11. 현재 코드·문서 불일치 메모

공동연구자가 노트북 설명만 읽을 때 혼동할 수 있는 부분이다.

- Baseline 4의 첫 제목이 아직 `Baseline 3`으로 적혀 있다.
- Baseline 5 첫 설명에는 워밍업 8회·`k=50`이라고 적힌 부분이 있지만 실제 실행 코드는
  워밍업 15회·`k=40`을 사용한다. 이 문서는 실행 코드를 기준으로 비교했다.
- Baseline 6의 Step 6 설명 일부는 `baseline_5_results.csv`를 언급하지만 실제 저장 파일은
  `baseline_6_results.csv`와 `baseline_6_summary.csv`다.
- 같은 Step 6 설명에는 Persistence·SVR도 적혀 있지만 실제 Baseline 6 실험 러너는
  세 종류의 LSTM만 실행한다.
- 노트북 출력 영역은 수정 전 실행 결과가 남아 있을 수 있으므로 소스 코드와 출력 문자열이 다르면
  소스 코드를 우선해 판단해야 한다.
