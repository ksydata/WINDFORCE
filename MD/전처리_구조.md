# 전처리 구조

`Windforce/` 패키지가 예보(LDAPS·GFS)·실측(SCADA) 세 소스를 **같은 8단계 템플릿**으로
전처리해서, LSTM이 바로 받는 3차원 배열까지 만들어내는 구조를 정리한다.
변경 이력은 [전처리_모듈화_변경사항.md](./전처리_모듈화_변경사항.md) 참고.

---

## 1. 전체 구조

```
Windforce/
├── FeatureEngineer.py         BasePreprocessor(추상). 8단계 템플릿 + 공통 계약
├── LDAPSFeatureEngineer.py    16격자 예보 전처리
├── GFSFeatureEngineer.py      9격자 예보 전처리 (고도 외삽 전용)
├── SCADAFeatureEngineer.py    10분 실측 정제 + 시간 집계
├── PreprocessorFactory.py     source 문자열로 위 셋을 생성
├── WindforceDataLoader.py     (전처리 이전 단계) 파일 경로 확인 + 원본 로드
├── utils/
│   ├── wind_utils.py          바람·대기 물리 계산 순수함수
│   ├── spatial_utils.py       격자 좌표·IDW 공간가중 순수함수
│   └── time_utils.py          시간축·범주·시퀀스 변환 순수함수
└── __init__.py                공개 API
```

**전처리 범위 밖** (참고용으로만 표기): `EvaluationMetrics.py`(평가지표),
`ScoreLossFunction.py`(손실함수, torch 필요), `Modeling/`(학습 파이프라인).
이 문서는 전처리(=모델 입력을 만드는 단계)까지만 다룬다.

---

## 2. 데이터 흐름

```
LDAPS raw (16격자) ─┐
GFS raw   (9격자)  ─┼─ BasePreprocessor.preprocess() ─ transformToGroupIDW ─┐
SCADA raw (17기)   ─┘   (소스별 8단계 템플릿)          transformToGroupHourly┘
                                                              │
                                                    그룹×시간 표 merge
                                                              │
                                          utils.time_utils.transform_to_model_input
                                                              │
                                    compute_feature_columns → transform_scale(학습구간만)
                                                              │
                                          utils.time_utils.transform_to_sequence
                                                              │
                                    (samples, 24, features) ─→ LSTM 입력
```

- LDAPS·GFS는 **격자 → KPX 그룹**(`transformToGroupIDW`, 역거리가중)으로 좁히고,
  SCADA는 **터빈 → 그룹**(`transformToTurbineHourly` → `transformToGroupHourly`)으로 좁힌다.
- SCADA는 최종 모델 입력이 아니다. 평가 기간엔 SCADA가 없으므로, LDAPS 10m 풍속을
  허브 높이로 보정하는 모델의 **정답값**·파워커브 분석에만 쓴다.

## 3. BasePreprocessor 8단계 템플릿

`preprocess()`가 순서를 고정하는 템플릿 메서드고, 아래 8단계가 그 안의 훅이다.
**추상**은 소스마다 반드시 구현해야 하고, **훅**은 기본값이 `return df`라 필요한
소스만 오버라이드한다.

| 순서 | 메서드 | 종류 | 하는 일 | LDAPS | GFS | SCADA |
|---|---|---|---|:---:|:---:|:---:|
| 1 | `transformColumnName` | 추상 | 원본 컬럼명 → 표준 이름 통일 | ✅ | ✅ | ✅ |
| 2 | `transformTimeAxis` | 추상 | 시간 컬럼 datetime화 + 소스별 시간 메타 | ✅ | ✅ | ✅ |
| 3 | `checkPhysicalLimit` | 추상 | 원시값 물리한계 검사 → 플래그 | ✅ | ✅ | ✅ |
| 4 | `interpolateMissing` | 훅 | 짧은 결측 보간 | – | – | ✅ |
| 5 | `calculatePhysicalFeature` | 추상 | 소스별 물리 파생변수 계산 | ✅ | ✅ | ✅ |
| 6 | `checkDerivedFlag` | 훅 | 파생값 기준 추가 플래그 | ✅ | – | – |
| 7 | `transformCyclicFeature` | 훅 | 풍향·시간 주기성 인코딩(sin/cos) | ✅ | ✅ | ✅ |
| 8 | `select_group`(utils 함수 호출) | 구체 | `self.group`으로 필터링 | ✅ | ✅ | ✅ |

- LDAPS·GFS는 결측이 없어 4번을 안 쓰고, SCADA는 파생 플래그가 없어 6번을 안 쓴다.
- `source`·`COLUMN_MAP` 클래스 속성이 없으면 `__init_subclass__`가 **import 시점에** 막는다
  (`@abstractmethod`는 메서드만 강제하고 클래스 속성은 못 잡아서).

## 4. 파일별 역할

| 파일 | 핵심 클래스/함수 | 하는 일 |
|---|---|---|
| `FeatureEngineer.py` | `BasePreprocessor` | 8단계 템플릿, 입력 로드(`_load_data`)·검증(`validateData`), 스케일 파라미터 계산·역변환(`computeScaleParam`/`transformInverseScale`) |
| `LDAPSFeatureEngineer.py` | `LDAPSFeatureEngineer` | 16격자 예보. 물리 파생변수 → `transformToGroupIDW`(그룹 IDW) / `transformToGridStats`(대조군 단순통계) → `transformForecastFeature`(변화량·램프) |
| `GFSFeatureEngineer.py` | `GFSFeatureEngineer` | 9격자 예보. 10m/80m/100m 등 7개 레벨 바람 → 전단지수(alpha) → 허브높이(117m) 외삽 → `transformToGroupIDW` → `transformForecastFeature` |
| `SCADAFeatureEngineer.py` | `SCADAFeatureEngineer` | 10분 실측. `transformToLong`(wide→long) → 물리한계·고착·터빈불일치 플래그 9종 → QC 코드 → 짧은 결측만 보간 → `transformToTurbineHourly` → `transformToGroupHourly` |
| `PreprocessorFactory.py` | `PreprocessorFactory` | `create(source, group)`으로 LDAPS/GFS/SCADA 인스턴스 생성. 옛 오타 클래스명(`*FeatureEnginner`)은 별칭으로 하위호환 |
| `WindforceDataLoader.py` | `WindforceDataLoader` | (전처리 이전) `TRAIN`/`TEST` 경로 확인 + CSV/엑셀 원본 로드·캐시 |
| `__init__.py` | – | 위 클래스·함수 공개 API로 재노출. `ScoreLossFunction`은 torch 필요라 접근 시점에만 지연 로딩 |

## 5. utils/ 공통 함수

세 소스가 똑같이 쓰는 물리·공간·시간 계산은 클래스 밖 순수함수로 뺐다
(상속 대신 조합, 테스트하기 쉬움).

### wind_utils.py — 바람·대기 물리

| 함수 | 하는 일 |
|---|---|
| `compute_wind_speed` | U·V → 풍속 (`sqrt(u²+v²)`) |
| `compute_wind_direction` | U·V → 풍향 (`arctan2(-u,-v)`, 0~360 정규화) |
| `compute_uv_component` | 풍속·풍향 → U·V (역변환) |
| `compute_angle_difference` | 두 각도의 최단 차이 (350°−10°=−20°, 340° 아님) |
| `compute_wind_shear` | 두 고도 풍속으로 전단지수(alpha) 계산 |
| `calculate_air_density` | 기온·비습·기압 → 수증기압(`e_pa`)·공기밀도 |
| `calculate_wind_power_density` | 공기밀도·풍속 → 풍력에너지밀도 (`0.5ρV³`) |
| `transform_wind_direction` | 풍향 컬럼들을 sin/cos으로 주기성 인코딩 |

### spatial_utils.py — 격자·공간가중

| 함수/상수 | 하는 일 |
|---|---|
| `KPX_GROUPS` | `("kpx_group_1", "kpx_group_2", "kpx_group_3")` |
| `PreprocessingError` | 전처리 계약 위반 시 던지는 공통 예외 |
| `compute_haversine_distance` | 위경도 두 점 사이 대권거리(km) |
| `compute_group_weight` | 터빈-격자 거리로 역거리가중(IDW, k=4) 행렬 계산 → 설비용량으로 그룹 가중 |
| `transform_to_group_feature` | 격자별 피처를 그룹 가중치로 공간 평균 (시각×격자 pivot → 행렬곱) |

### time_utils.py — 시간축·시퀀스

| 함수/상수 | 하는 일 |
|---|---|
| `transform_cyclic_time` | 시간→ hour/dayofyear sin·cos, month, season |
| `transform_categorical` | 범주형 원핫 (카테고리 고정 가능, 계절 4종 차원 흔들림 방지) |
| `interpolate_short_gap` | 결측 **구간 전체 길이**를 재서 `max_steps` 이하인 구멍만 선형보간 |
| `transform_group_time_feature` | 격자 단위 시간 피처를 그룹 표에 복원 (공간가중 통과 시 유실 방지) |
| `transform_forecast_diff` | 그룹별 시계열 변화량·3시간 램프·풍향 회전량 |
| `select_group` | `group` 컬럼 기준 필터링 (8단계의 마지막 단계) |
| `transform_to_model_input` | 정렬 + bool→int8 + season 원핫 등 모델 입력 정리 |
| `compute_feature_columns` | 시간·키·타깃 제외한 수치형 컬럼 목록 |
| `transform_scale` | (평균, 표준편차)로 표준화 |
| `transform_to_sequence` | 그룹별로 `seq_len` 슬라이딩 윈도우 → `(samples, seq_len, features)` |

## 6. 사용법

```python
from Windforce import PreprocessorFactory

fe = PreprocessorFactory.create("ldaps")          # "gfs"도 동일
group_df = fe.preprocess(ldaps_raw)                # 8단계 템플릿 실행 (그룹 필터 없이 전체)
grid_group = fe.transformToGroupIDW(group_df, turbine_meta)
feat = fe.transformForecastFeature(grid_group)
```

주의: `SCADAFeatureEngineer`는 생성 시 `turbine_meta`가 필수다
(터빈마다 정격·컷아웃이 달라 행별 물리한계 기준을 못 만든다).
